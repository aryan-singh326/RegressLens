# Trace database (schema v2)

`~/.regresslens/traces.db` (override with `RGLNS_DB_PATH`), SQLite in WAL mode,
`PRAGMA user_version = 2`.

| table | one row per | columns |
|---|---|---|
| `sessions` | CLI invocation (`RGLNS_SESSION_ID`) | session_id, label, started_at, hw_fingerprint, git_sha, git_dirty, python, numpy, meta_json |
| `runs` | subprocess run (`RGLNS_RUN_ID`) | run_id, session_id, wall_ns, canary_compute_ns, canary_mem_ns, exit_code, started_at, canary_json |
| `calls` | run x call site x argument shape | run_id, call_site_id, operator, dtype, n, contiguous, kernel, count, sum_ns, sum_log_ns, sample_ns_json, extra_json |
| `call_sites` | call_site_id | path, qualname, ordinal, line, stack_json |

* `wall_ns` is the program's own run time, as reported by the measured process
  at exit: from the end of the bootstrap to exit, minus canary time. It excludes
  interpreter start-up and RegressLens's own bookkeeping, which are constant per
  run and would only dilute relative effects. The CLI's measurement around the
  process is the fallback.
* `canary_compute_ns` / `canary_mem_ns` are medians of the run's canary
  samples. All samples, with where and when each was taken, are in `canary_json`.
* `calls` rows are written once per process at exit. `sample_ns_json` is a
  64-sample reservoir. `extra_json` holds operation-specific sums (filter
  selectivity, rolling window, `n_bucketed` when a call site saw more than 64
  distinct sizes and further sizes were bucketed to quarter-octaves).
* `call_sites.stack_json` holds up to 8 normalized user frames
  (`{"path", "qualname", "line"}`); `rglns bisect` reads the paths.
* `hw_fingerprint` is JSON: system, machine, CPU model, logical CPUs, and
  L1d/L2/L3 sizes. Python and NumPy versions are separate columns, because
  upgrading NumPy is not a hardware change.

## Migration from v1

v1 had one flat `traces` table: one row per call, a free-form `run_label`
lumping all runs of a CLI invocation together, and (operator, dtype,
row_count) standing in for call-site identity. Opening a v1 database migrates
it in one transaction:

* the original table is kept verbatim as `legacy_traces_v1`;
* each v1 `run_label` becomes a session (`meta_json.migrated_from = "v1"`) with
  a single run, because v1 never recorded run boundaries;
* rows are aggregated into `calls` (count, sums, a deterministic 64-sample
  subset), with `call_site_id = sha1("v1|<file:line>|<operator>")`.

`tests/fixtures/v1_traces.db` was generated by the v0.1 code itself
(`tests/fixtures/make_v1_db.py` loads it from git history), and
`tests/test_store.py` checks that every row survives and that `rglns profile`
runs on the result.
